# Automated screening, audit trail

`protocol.txt` is the frozen title/abstract triage rule. `run_triage.py` calls the user-configured OpenCode model named in the run manifest. This is automated preliminary triage, not a human independent review and not an eligibility decision. Input `../search_protocol/records.csv` is checked against its frozen SHA-256 before use. Each batch retains its full prompt, model event stream, timestamps, errors and each attempted response in `batches/`; invalid or missing batches are not treated as exclusions. Model-provider snapshot and generation parameters were not exposed by the OpenCode CLI.

Run `python3 aggregate.py` after or during screening. It emits one row per input, including `NOT_SCREENED` for failed or unrun batches. It preserves `raw_model_decision`. For conservatism it changes an `EXCLUDE` to `UNCLEAR` when the abstract is missing, the alleged supporting excerpt cannot be matched exactly to the supplied title/abstract, or an OS-target keyword or known seed matches. The executable keyword and seed list is in `postprocess_policy.py`; the reason appears in `override_reason`. This broad safeguard cannot guarantee recall and does not verify any remaining decision. The `year_scope` field uses the supplied year only; it does not establish a work's earliest publication date or exact cutoff eligibility.

The model's evidence snippets can be wrong even when the decision is plausible. `evidence_match` checks whether a quoted string occurs verbatim, not whether the rationale is correct. Source metadata can contain errors, and exact-identifier deduplication can leave versions unmatched. All `POSSIBLE_CORE`, `EXCLUDE`, and `UNCLEAR` labels require independent review before a publication eligibility flow can be reported. `pilot_v1_batch_0000/` is an archived pilot and is not part of the frozen v2 run.

If a second pass exists, `second_pass/` contains separate prompts and responses for records with available abstracts. It is a new run of the same model, without first-pass decisions in its prompt; it is not a second human reviewer. Disagreements must remain pending until independently adjudicated.

The 2026-11-05 snapshot contains 6,408 records. The completed first pass has 93 `POSSIBLE_CORE`, 1,660 `EXCLUDE` and 4,655 `UNCLEAR` after the conservative overrides; there are 168 non-matching evidence snippets and 13 records without source text. For the 2,311 records with abstracts, the second pass has 2,195 agreements and 116 disagreements after the same safeguards. `python3 compare_passes.py` regenerates the comparison; agreement is not a verified screening decision. The separately obtained arXiv pagination extension has 1,168 additional records; its input SHA-256, prompts, responses and separate preliminary counts are in `arxiv_extension/`. The pagination happened over a period during which rankings might have changed. No disjointness beyond the documented exact-ID matching is asserted.

The client reported `opencode v2.2.5`; the model alias was `deepseek/deepseek-flash`. The provider did not expose a pinned model snapshot, temperature or other generation parameters. The second pass used separate model sessions and did not receive first-pass decisions, but both passes used the same model and are not independent researchers. Repeated model calls may return different outputs; replaying the saved model responses and deterministic postprocessing reproduces the reported labels, whereas another model run need not.

`priority_review_queue.csv` is built by `build_priority_queue.py` from saved decisions and audit/citation records. It combines OS-keyword/seed safeguards with possible-core items, inter-run disagreements, audit disagreements, known seeds and cited-work matches, with each trigger recorded. `high_priority_review_queue.csv` omits records whose only trigger is an OS keyword after model exclusion; all omitted automated decisions remain preliminary. The stratified audit was sampled on the earlier pre-keyword-guard version, preserved separately at `../audit/screening_results_sample_frame.csv` with its fixed SHA-256. Do not conflate the two frames. `third_pass/` contains model rechecks of the high-priority records with available abstracts under `third_review_protocol.txt`, with no first- or second-pass decisions supplied to that prompt. Missing-abstract records remain pending; a third model call still does not constitute final eligibility review.

The third pass covered 197 records; 37 high-priority records lacked abstracts and were not sent to this pass. Of the 197, 56 model-provided excerpts did not match their source text exactly. `finalize_third_review.py` preserves the raw suggestion and conservatively sets all 56 effective suggestions to `unclear`; every record remains pending independent verification. Model agreement is not an accuracy estimate.

`crosssource/` contains a separate supplemental model call for four of the 37 records, using saved original abstracts from matched records in the existing snapshot. `source_manifest.json`, `supplemented_records.csv`, and `../audit/missing_abstract_crosssource.csv` preserve the matching rules, source record IDs, URLs and checksums. This supplement neither alters the first-pass snapshot nor makes the matched records new search hits. The other 33 high-priority records still lack a matched original abstract from this local-source check. The four supplemental model suggestions also remain pending verification.

The first-pass `run_manifest.json` was overwritten by the final retry invocation and records its two-worker configuration, not the initial 16-worker call. `first_pass_invocation_history.json` records both invocations: time ranges are computed from retained batch attempt metadata, while worker counts are from the observed command invocations. `build_invocation_history.py` regenerates the time-range record.

For offline verification, run from the repository root: `python3 reproduct/screening/verify_saved_responses.py` to compare saved successful event streams and parsed batch results; `python3 reproduct/screening/verify_replay.py` to recompute the two screening summaries, second-pass comparison, third-pass conservative suggestions and review queues; and from `reproduct/`, `shasum -a 256 -c screening/SHA256SUMS` to verify the frozen evidence files. These checks establish consistency, not correctness or comprehensive recall.
